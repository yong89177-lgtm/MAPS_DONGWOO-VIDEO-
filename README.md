# AI Agent 마켓

메인 화면에서 `+ AI Agent 등록` 버튼을 눌러 HTML 파일 기반 AI 에이전트를 등록 요청하고,
관리자가 **1차 승인 → 2차(최종) 승인**을 거치면 카테고리별 영역에 카드가 노출됩니다.
카드를 클릭하면 등록 시 업로드한 HTML 파일이 그 자리에서 실행됩니다.

## 실행 방법

```bash
npm install
cp .env.example .env   # ADMIN_KEY를 원하는 값으로 변경
npm start               # http://localhost:3000
```

개발 중에는 `npm run dev` (nodemon)로 실행하면 서버 코드 변경 시 자동 재시작됩니다.

- 메인 페이지: `/index.html`
- 관리자 승인 페이지: `/admin.html` (상단에 `.env`의 `ADMIN_KEY` 값을 입력해야 목록이 보입니다)

## 등록 → 승인 → 노출 흐름

1. 사용자가 메인 화면에서 이름/카테고리/설명/등록자/이메일/HTML 파일을 입력하고 "요청 보내기"를 누르면
   `POST /api/agents` 로 전송되어 `pending`(대기중) 상태로 저장됩니다. (이전에 백엔드가 없어 "서버에
   연결할 수 없습니다" 오류만 뜨던 부분을 실제 동작하는 API로 구현했습니다.)
2. 관리자가 `/admin.html`에서 대기중 항목을 확인하고 **1차 승인**하면 `first_approved` 상태가 됩니다.
3. 1차 승인된 항목을 관리자가 **2차(최종) 승인**하면 `approved` 상태가 되고, 그 시점부터 메인 화면의
   해당 카테고리 영역에 카드로 노출됩니다. 두 단계 중 어디서든 "거절"이 가능하며 사유를 입력할 수 있습니다.
4. 메인 화면에서 카드를 클릭하면 `GET /api/agents/:id/file` 로 승인된 HTML 파일을 iframe에 불러와
   그 자리에서 실행합니다 ("새 탭에서 열기" 링크도 제공됩니다).

## 데이터 저장

별도 DB 없이 `data/db.json` 파일에 요청/승인 이력을 저장하고, 업로드된 HTML 파일은 `uploads/`에
`<요청 id>.html` 형태로 저장됩니다. 소규모 데모/내부용으로 충분하지만, 운영 규모가 커지면 실제
데이터베이스(PostgreSQL 등)와 오브젝트 스토리지로 교체하는 것을 권장합니다.

## 인증

관리자 API(`/api/agents/admin`, `first-approve`, `second-approve`, `reject`, `preview`)는
`.env`의 `ADMIN_KEY` 값을 `x-admin-key` 헤더(또는 `?key=` 쿼리)로 전달해야 호출할 수 있습니다.
지금은 간단한 공유 키 방식이며, 실제 운영에서는 로그인 기반 관리자 계정/세션으로 교체를 권장합니다.

## 보안 참고

- 업로드는 `.html`/`.htm` 확장자만 허용하고 3MB로 제한합니다.
- 승인되지 않은 에이전트의 HTML은 공개 라우트(`/api/agents/:id/file`)로 접근할 수 없습니다
  (관리자 미리보기 전용 라우트만 가능).
- 업로드된 HTML은 사용자가 직접 작성한 콘텐츠이므로, 실행 시 `sandbox` 속성이 적용된 iframe
  안에서만 열립니다.
